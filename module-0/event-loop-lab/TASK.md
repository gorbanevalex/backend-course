# ДЗ 0.1: Лаборатория event loop

**Контекст.** До кода проекта ещё один модуль, но эта лаба — фундамент. На собесе тебя спросят: «Что будет, если в обработчике…», и у тебя будут не заученные фразы, а собственные замеры.

## Требования
1. HTTP-сервер на голом `node:http` (без фреймворков). Порт берётся из переменной окружения `PORT`, по умолчанию `3000`.
2. Ручки:
   - `GET /fast` — сразу отвечает `ok`;
   - `GET /cpu?ms=N` — синхронно занимает CPU на N мс, потом отвечает;
   - `GET /io?ms=N` — ждёт N мс, **не** блокируя event loop, потом отвечает;
   - `GET /hash` — асинхронный `crypto.pbkdf2` с параметрами, при которых хеш считается примерно 300–500 мс на твоей машине;
   - `GET /file` — асинхронно читает какой-нибудь файл с диска и отвечает его размером.
3. Раз в секунду сервер пишет в stdout **задержку event loop**: насколько loop опаздывал за последнюю секунду. Как это измерить, найди сам. Подходят и самодельный вариант, и встроенное в Node API.
4. Скрипт `bench.js` (без npm-зависимостей, только встроенное в Node) прогоняет сценарии и печатает задержку ответа `/fast` или `/file` в каждом:
   - **A:** запрос `/cpu?ms=3000`, через 100 мс запрос `/fast`;
   - **B:** запрос `/io?ms=3000`, через 100 мс запрос `/fast`;
   - **C:** 10 параллельных `/hash`, через 50 мс запрос `/file`. Прогони три раза: с пулом по умолчанию, с `UV_THREADPOOL_SIZE=1` и с `UV_THREADPOOL_SIZE=10`.
5. `REPORT.md` с таблицей замеров (сценарий → задержка → что показывал лог задержки event loop) и объяснением **своими словами** для каждого сценария: почему цифры именно такие.

## Критерии приёмки
- [ ] `PORT=4000 node server.js` поднимает сервер на 4000, а без переменной сервер слушает 3000
- [ ] В сценарии A `/fast` ждёт ~3 с, в сценарии B отвечает за единицы миллисекунд; лог задержки event loop это подтверждает
- [ ] В сценарии C задержка `/file` заметно меняется в зависимости от размера пула, и в отчёте объяснено, почему
- [ ] Неизвестный путь возвращает `404`; невалидный `ms` (не число, отрицательный, огромный) возвращает `400` и не вешает сервер
- [ ] `REPORT.md` можно прочитать, не запуская код, и всё понять

## Ограничения
Никаких npm-зависимостей и фреймворков, только `node:*`. Смысл лабы в том, чтобы увидеть механику без обёрток. JS или TS на твой выбор (Node 22+ умеет запускать `.ts` с флагом `--experimental-strip-types`, а начиная с 23.6 без флага).

## Бонус
- `GET /cpu-worker?ms=N`: та же CPU-работа, но `/fast` во время неё не страдает. Добавь сценарий в `bench.js` и замер в отчёт.
- `GET /validate?email=...` с уязвимой регуляркой плюс защита от ReDoS. Покажи в отчёте замер до и после защиты.
