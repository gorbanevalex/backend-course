# Роадмап: от фронтенда к fullstack

Каждый модуль занимает 2–6 сессий. Все ДЗ развивают сквозной проект: трекер задач для команд с бронированием переговорок.
Модули 0–5 — фундамент, их не пропускаем. Порядок остальных можно менять.
Темп ~11 ч в неделю → весь путь примерно 7–9 месяцев.

## Модуль 0. Node.js как серверная среда 🟡
- ✅ Сервер ≠ браузер: долгоживущий процесс, общий для всех пользователей
- ✅ Event loop на сервере: фазы, микрозадачи, что блокирует; libuv, пул потоков
- ⚪ `worker_threads` (на практике — в бонусе ДЗ 0.1)
- ⚪ `process.env`, сигналы, exit codes, stdout/stderr; ESM vs CJS
- ⚪ Buffer и Streams, backpressure

**ДЗ:** 0.1 — лаборатория event loop (🟡 выдано); 0.2 — CLI, потоково обрабатывающий лог на 1 ГБ с ограниченной памятью

## Модуль 1. HTTP с серверной стороны
- Сервер на голом `node:http`: разбор URL, тела запроса, роутинг руками
- Семантика методов, идемпотентность, статус-коды, заголовки, content negotiation
- Cookies (HttpOnly, Secure, SameSite), CORS и preflight — теперь с другой стороны
- Keep-alive, обзор HTTP/2 и TLS

**ДЗ:** CRUD-API первой сущности проекта на голом `node:http` (хранение в памяти или файле), корректные коды, валидация, CORS для своего фронта

## Модуль 2. Фреймворк, дизайн API и структура приложения
- Что дают фреймворки (Fastify/Express): роутинг, хуки и middleware, сериализация, плагины
- REST-дизайн: ресурсы, пагинация (offset vs cursor), фильтры, версионирование, формат ошибок (Problem Details, RFC 9457), OpenAPI
- Валидация схемами (zod/TypeBox), типобезопасность от схемы
- Слои: transport → service → repository; внедрение зависимостей
- Конфигурация и логирование (pino)

**ДЗ:** перенести проект на фреймворк, разделить на слои, OpenAPI-спецификация, пагинация и фильтры

**Бонус 2+:** перенос на Nest.js — понять, что делает каждый декоратор под капотом

## Модуль 3. Реляционные БД и SQL
- Минимум Docker: запуск Postgres, порты, volumes, docker compose
- Моделирование: сущности, связи 1:N и N:M, нормализация, ключи, constraints
- SQL: JOIN, GROUP BY, подзапросы, CTE, оконные функции
- Индексы: B-tree, составные индексы, EXPLAIN ANALYZE, когда индекс не помогает
- Транзакции, ACID, уровни изоляции и аномалии, блокировки, MVCC

**ДЗ:** ER-схема проекта, миграции на чистом SQL, запросы под бизнес-вопросы, ускорить медленный запрос с доказательством через EXPLAIN

## Модуль 4. База данных из приложения
- Драйвер, параметризованные запросы vs SQL-инъекции, пул соединений
- Инструмент миграций, сиды
- Query builder vs ORM (Kysely/Drizzle/Prisma), проблема N+1
- Транзакции в коде; гонки (двойное бронирование); оптимистичные и пессимистичные блокировки; уникальные ограничения

**ДЗ:** подключить Postgres к API; операция в транзакции и скрипт конкурентных запросов, доказывающий, что гонки нет

## Модуль 5. Тестирование бэкенда
- Пирамида тестов на бэке; что мокать, а что нет
- Интеграционные тесты с реальной БД (testcontainers), изоляция тестов
- Тесты HTTP-слоя (inject/supertest), фабрики данных

**ДЗ:** покрыть ключевые и ошибочные сценарии; тесты должны ловить гонку из модуля 4

## Модуль 6. Аутентификация, авторизация, безопасность
- Хеширование паролей (argon2/bcrypt) и почему не sha256
- Сессии в cookie vs JWT: отзыв, refresh-ротация, хранение на клиенте
- OAuth 2.0 / OIDC: authorization code + PKCE
- RBAC, проверка владения ресурсом (IDOR/BOLA)
- OWASP API Security Top 10, rate limiting, управление секретами

**ДЗ:** регистрация и логин, защищённые ручки, роли, проверка владения; самоаудит по OWASP API Top 10. Бонус: вход через внешнего OAuth-провайдера

## Модуль 7. Кеширование и Redis
- HTTP-кеш (ETag, Cache-Control), in-memory, Redis
- Cache-aside, write-through, TTL, инвалидация, cache stampede
- Redis как rate limiter, хранилище сессий, распределённые локи

**ДЗ:** кеш тяжёлой ручки с инвалидацией, rate limiter на Redis, замер нагрузочным тестом до и после

## Модуль 8. Асинхронная обработка и очереди
- Очереди (BullMQ, RabbitMQ), воркеры
- At-least-once доставка, идемпотентные обработчики, retries с backoff, dead letter queue
- Transactional outbox, вебхуки, планировщик задач

**ДЗ:** уведомления через очередь с идемпотентным воркером и outbox; доказать, что при падении воркера ничего не теряется и не дублируется

## Модуль 9. Realtime и другие протоколы
- WebSocket и SSE на сервере; масштабирование через Redis pub/sub
- GraphQL: резолверы, N+1, DataLoader
- gRPC — обзор

**ДЗ:** realtime-обновления в проекте, работающие при двух запущенных инстансах

## Модуль 10. Контейнеры, CI/CD и деплой
- Dockerfile: multi-stage, non-root, кеш слоёв; compose для всего стека
- 12-factor app, конфигурация и секреты
- CI (GitHub Actions): линт, тесты с БД, сборка образа
- Деплой: VPS или PaaS, reverse proxy, TLS, миграции при деплое, zero-downtime

**ДЗ:** задеплоить проект с фронтом; зелёный CI; автоматические миграции

## Модуль 11. Наблюдаемость и эксплуатация
- Структурированные логи, request id, метрики (Prometheus), трейсинг (OpenTelemetry)
- Health/readiness checks, graceful shutdown, таймауты и retries
- Нагрузочное тестирование, профилирование CPU, поиск утечек памяти

**ДЗ:** логи, метрики и трейсинг; нагрузочный тест; найти и устранить узкое место с цифрами до и после

## Модуль 12. Архитектура и масштабирование
- Stateless-сервисы, горизонтальное масштабирование, балансировка
- Репликация, read replicas, партиционирование и шардирование, CAP/PACELC
- Монолит, модульный монолит, микросервисы; основы DDD
- Как проходить system design интервью

**ДЗ:** дизайн-документ масштабирования проекта под x100 нагрузку + 2 задачи system design в формате собеседования
