## Пройдено
- Run-to-completion: синхронный код нельзя прервать, loop ждёт пустой стек
- Процесс сервера общий для всех пользователей: блокировка у одного — тормоза у всех
- «Долгий ≠ блокирующий»: ожидание I/O не блокирует, CPU-работа блокирует
- libuv: два механизма — поллер ОС (сеть, без потоков) и пул потоков (fs, dns.lookup, crypto, zlib; UV_THREADPOOL_SIZE, по умолчанию 4)
- Эксперимент с pbkdf2 и размером пула: выполнен и объяснён (группировка 4 + 2)
- Забитый пул тормозит несвязанные ручки (очередь FIFO)
- Запросы в БД идут через поллер ОС, пул потоков не занимают
- Фазы loop: timers → poll → check → close; микрозадачи (nextTick → промисы) после каждого колбэка
- Фаза определяется типом колбэка; setTimeout(fn, 0) = «на ближайшей фазе timers»
- Пример с readFile: порядок sync → nextTick → promise → immediate → timeout, объяснён
- Что такое I/O vs CPU; «асинхронный API ≠ I/O» (bcrypt)
- Шпаргалка: docs/event-loop-cheatsheet.html
