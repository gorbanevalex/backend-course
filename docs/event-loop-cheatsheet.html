Event loop в Node.js

Шпаргалка к модулю 0: модель, фазы и пошаговый прогон примера.

Модель в трёх блоках

Один JS-потокВесь твой JavaScript выполняется в одном потоке, общем для всех запросов. Колбэк выполняется до конца (run-to-completion), прервать его нельзя.
libuv: поллер ОС + пул потоковСеть (HTTP, БД, Redis) идёт через поллер ОС, без потоков. Файлы, dns.lookup, часть crypto и zlib идут в пул (по умолчанию 4 потока, UV_THREADPOOL_SIZE). Результат всегда возвращается колбэком в JS-поток.
Loop — круг из четырёх очередейtimers → poll → check → close → снова timers. В каждой фазе выполняется то, что готово в её очереди, потом loop едет дальше. Назад не возвращается.
После каждого колбэка в любой фазе: сначала все process.nextTick, потом все промисы, до дна. Только потом loop двигается дальше.

Главные выводы

  • setTimeout(fn, 0) означает «на ближайшей фазе timers», а не «сейчас». Если loop уже проехал timers на этом круге, колбэк ждёт следующего круга.
  • Микрозадачи выполняются раньше любой следующей фазы. Бесконечная цепочка промисов или nextTick вешает сервер так же, как while.
  • Пока выполняется синхронный код, круг стоит. Поэтому тяжёлая CPU-работа в обработчике тормозит всех клиентов.
  • Процесс живёт, пока loop'у есть чем заниматься: таймеры, открытые сокеты, задачи в пуле. server.listen() держит сокет открытым, поэтому сервер не завершается.
